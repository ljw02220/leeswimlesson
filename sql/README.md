# Supabase SQL 최종 정리본

Supabase SQL Editor에는 아래 다섯 개만 현재 설정으로 관리합니다. 파일 전체를 복사하고, **01 → 02 → 03 → 04 → 05** 순서로 각각 실행하세요. 처음 정리본을 적용할 때는 다섯 개 모두 실행합니다.

| 순서 | 저장할 쿼리 이름 | 파일 | 포함 내용 |
| --- | --- | --- | --- |
| 01 | 기본 DB 스키마 | [01-base-schema.sql](01-base-schema.sql) | 회원·수업·재무·가입 신청, 역할별 권한, 자유수영, 테스트 계정 조회 |
| 02 | 보강관리 | [02-makeup-management.sql](02-makeup-management.sql) | 보강 시간·신청·승인·반려·취소, 횟수 요청·승인·사용·복원 |
| 03 | 수업 댓글 기능 | [03-lesson-comments.sql](03-lesson-comments.sql) | 기본 댓글·대댓글·삭제 표시, 수업노트·댓글 알림 조회 |
| 04 | 입금·보고·동기화 | [04-payments-and-reports.sql](04-payments-and-reports.sql) | 결제 알림·입금 확인·보고 완료, 입금 건 ID 연결과 수정 동기화 |
| 05 | 알림 | [05-notifications.sql](05-notifications.sql) | 가입·보강·댓글·수업노트 푸시 대기열과 트리거 |

## 실행 방법

1. 기존 저장 쿼리는 이름 앞에 `이전_`을 붙여 보관합니다. 테이블을 삭제하지 않습니다.
2. 위 다섯 이름으로 새 쿼리를 만들고 파일 내용을 전체 복사합니다.
3. 01부터 순서대로 Run을 눌러 실행합니다. 저장만으로 DB에 적용되지 않습니다.
4. 다섯 개 모두 성공한 뒤 사이트를 새로고침합니다. 기존 SQL 쿼리 탭을 삭제해도 이미 저장된 DB 데이터나 함수가 삭제되지는 않습니다.
5. 이후 한 기능을 수정하면 해당 파일 전체를 실행합니다. 새 테이블 의존성이 추가된 변경은 안내된 순서를 따릅니다. 예전 파일을 나중에 재실행하면 최신 함수가 덮어써지므로 사용하지 않습니다.

## 기존 데이터와 권한

- 테이블 삭제·초기화, 과거 입금 날짜/금액 일괄 덮어쓰기, 샘플 회원 생성은 하지 않습니다.
- 9월 29일 댓글을 조회하거나 시간을 20시에서 19시로 바꿨던 일회성 쿼리는 포함하지 않았습니다. 이미 수정된 값은 유지합니다.
- 04는 아직 연결되지 않은 기존 보고서를 동일 회원·입금일·금액이 일치하고 보고 생성 전에 확인된 입금에 연결할 수 있습니다. `payment_request_id`만 채우고 날짜·금액·보고일은 변경하지 않습니다. 연결할 수 없는 과거 기록은 추정으로 덮어쓰지 않습니다.
- 기존의 `authenticated ... access` 전체 허용 정책을 정리합니다. 관리자는 전체 관리, 일반 회원은 본인 기록 조회 및 전용 함수로 신청/댓글 작성, 테스트 계정은 별도 RPC를 통해 전체 회원을 조회합니다. 일반 회원과 테스트 계정은 다른 회원 자료를 직접 수정할 수 없습니다. 단체수업 기록은 회원 공통 조회입니다.
- 승인된 가입 신청과 전화번호가 일치하고 Auth 계정이 아직 연결되지 않은 회원은 첫 로그인 시 본인 Auth ID만 연결할 수 있습니다. 이름·수강료 등 일반 회원 정보 수정은 관리자만 가능합니다.
- 프로젝트에 모르는 이름으로 추가한 정책이 있다면 별도 확인이 필요합니다. 이 정리본은 확인된 기존 정책만 교체합니다.

## 자유수영 / 테스트 계정

- 자유수영은 01에 통합했습니다. 회원·날짜별 한 건이며, 본인만 기록·취소하고 미래 날짜는 한국 시간 기준으로 차단합니다. 수업 횟수나 결제에 영향을 주지 않습니다.
- 기존 `01010101010@members.leeswimlesson.com` Auth 계정과 연결 회원을 찾으면 이름을 ‘테스트’로 변경하고 전체 회원 조회 권한을 부여합니다. 로그인 번호·비밀번호·기존 기록은 유지합니다. 해당 계정이 없으면 건너뛰며 새 계정이나 비밀번호를 만들지 않습니다.
- 테스트 조회 함수는 01에 정의하지만 조회 대상 테이블은 나머지 파일에 있으므로 다섯 개를 모두 실행한 뒤 사용하세요.

## 알림 서버

사이트 내 알림 조회와 휴대폰 푸시는 별개입니다. 05만 실행해도 휴대폰 알림이 자동 발송되는 것은 아닙니다. 기존 `web-push` Edge Function, VAPID 키, `push_notification_events` INSERT 웹훅, 기기별 알림 허용 설정이 필요합니다. SQL에 비밀 키를 넣지 않습니다.

## 검증 범위

- 로컬 임시 PostgreSQL 엔진(PGlite, Supabase Auth 스키마/역할 모사)에서 신규 설치 01~05 순서 실행과 재실행을 검증했습니다.
- 이전 기본 스키마·댓글 정의 및 샘플 기존 기록이 있는 상태의 업그레이드·재실행, 기존 댓글/보고 보존을 검증했습니다.
- 일반 회원의 타 회원 수정 차단, 테스트 계정의 전체 회원 조회, 대댓글 작성 및 부모 삭제 후 답글 유지, 자유수영 소유권·미래 날짜 제한을 검증했습니다.
- 동일 날짜·금액의 별도 입금 건 보고, 과거 보고 수정 시 현재 입금 보존, 현재 입금 수정의 해당 보고 동기화, 반복 확인을 검증했습니다.
- 실제 Supabase 운영 DB에는 실행하지 않았습니다. 운영 DB의 알 수 없는 추가 정책·트리거 및 실제 휴대폰 푸시 수신은 이 검사에 포함되지 않습니다.

원본 8개 파일은 `archive/2026-11-24/`에 보관했습니다. 보관본과 프로젝트 최상위의 예전 `supabase-*.sql`은 현재 실행용이 아닙니다.

## 수업 내용 없이 댓글 작성

03은 등록된 수업 요일·시간에 대해 관리자 수업 기록이나 메모가 없어도 댓글/답글을 저장할 수 있습니다. 댓글 작성으로 수업 레코드·완료 상태·잔여 횟수를 변경하지 않습니다. 사이트 댓글 알림은 해당 날짜의 홈 달력으로 연결됩니다. 이 변경은 최신 03과, 휴대폰 댓글 알림 연결을 위한 최신 05를 다시 실행해야 합니다.

## 개인레슨 한 회 일정 변경

최신 01과 05를 다시 실행하면 개인레슨 일회성 일정 변경과 변경 알림을 사용할 수 있습니다. 수업관리에서 예정된 개인레슨을 날짜 칸으로 끌거나, 상세 창의 ‘일정 변경’에서 날짜·시간을 지정합니다. 모바일은 길게 누른 뒤 끌거나 상세 창 버튼을 사용합니다.

`personal_lesson_moves`에 원래 회차와 새 날짜·시간을 연결하며, 회원의 정기 요일·시간 및 등록/진행 횟수는 수정하지 않습니다. 같은 회차를 다시 옮기면 기존 변경을 갱신합니다. 수업 내용과 해당 댓글은 변경된 날짜·시간으로 이동합니다. 완료/취소/삭제된 회차는 옮기지 못합니다. 관리자 홈·수업관리·회원 달력·개인레슨 예상 마감일에서 변경을 반영합니다. 변경 알림의 실제 휴대폰 발송에는 기존 푸시 서버 설정이 필요합니다.

## 날짜별 수영거리와 월 합계

최신 01을 다시 실행하면 기존 오수완 테이블에 `distance_meters`가 추가됩니다. 이전 도장은 거리 미입력(null)으로 유지합니다. 날짜를 길게 눌러 자유수영 거리를 정수 미터로 입력/수정합니다. 날짜별 한 건을 갱신하며, 현재 선택한 달에 직접 입력한 거리만 월 합계로 표시합니다. 거리를 저장하면 오수완도 함께 표시됩니다. 도장만 기록하는 것도 가능하고, 기록을 삭제하면 해당 날짜 거리도 합계에서 빠집니다. 일반 회원은 본인의 거리만 수정할 수 있습니다.


## 코치가 입력하는 수업 수영거리

최신 01에 `lessons.swim_distance_meters`가 포함됩니다. 관리자 홈의 수업 내용에 수업 수영거리(m)를 입력하고 함께 저장합니다. 이는 해당 수업에서 회원 한 명이 수영한 거리입니다. 회원은 본인 개인레슨·보강 또는 등록된 단체수업 거리만 합산하고, 취소·삭제·미래 날짜 수업은 월 합계에서 제외합니다. 같은 수업이 중복 저장된 경우 최신 기록 한 건만 합산합니다. 수업거리와 회원이 입력한 자유수영 거리를 합쳐 날짜별·월별 총거리를 표시합니다. 거리를 쓰지 않은 과거 수업은 0m로 추정하지 않고 합계에서 제외합니다. 기존 수업 상태와 잔여 횟수는 거리 저장으로 바뀌지 않습니다.

## 1레인 운동량 표

최신 01을 다시 실행하면 `lessons.workout_plan` JSONB 필드가 추가됩니다. 관리자 홈에서 수업을 선택하고 수업 내용 아래에서 준비운동·드릴·메인·마무리를 작성합니다. 거리·횟수·세트로 계획 총거리를 계산하며, 영법·강도·사이클·소요시간도 입력할 수 있습니다. 회원 홈의 해당 수업 내용 아래에는 읽기 전용 표가 표시됩니다. 예시는 1레인 1,300m입니다.

운동량 표를 저장하면 총거리를 `lessons.swim_distance_meters`에 함께 저장합니다. 별도 수업거리 입력란은 없으며, 표를 수정하면 달력과 월 합계에 반영되는 거리도 갱신됩니다. 표를 비우고 저장하면 거리도 지웁니다. 기존 수업의 진행 상태는 유지되고, 취소·삭제·미래 날짜 수업은 월 합계에서 제외합니다.

## 날짜별 공통 운동량

최신 01을 다시 실행하면 `daily_workouts`를 생성하고 기존 수업별 운동량 중 날짜별 최신 표를 옮깁니다. 관리자 홈의 어느 수업에서 저장하든 그 날짜 운동량 하나를 갱신하며, 회원은 당일 공통 표를 봅니다. 수업 메모·댓글·답글은 기존 수업별로 유지합니다. 거리는 회원의 수업이 있는 날짜에 하루 한 번 합산합니다.

## 회원 완료(참여)

최신 01의 `member_workout_participations`에 회원 본인의 날짜별 참여를 기록합니다. 관리자 수업 완료와 무관하게, 회원이 완료(참여)를 눌러야 공통 운동량을 하루 한 번 합산합니다. 참여 취소 시 합계에서 빠지며 자유수영은 유지합니다. 개인레슨·취소·삭제 수업은 공통 운동량 참여 대상이 아닙니다. 과거 참여는 자동 생성하지 않습니다.

회원 거리 합산 예외: 2026-11-24 이전 날짜는 회원의 참여 기록 없이 등록된 단체/보강 수업 운동량을 합산합니다. 2026-11-24부터는 회원 본인의 완료(참여)가 필요합니다. 개인레슨과 취소·삭제 수업은 제외합니다. 과거 참여 기록을 DB에 생성하지 않습니다.

## 정회원·준회원 기능 구분

개인레슨 수강 형태(1:1~1:5 등)가 있는 회원은 정회원, 단체수업만 수강하는 회원은 준회원입니다. 관리자 회원 수정의 ‘수업 형태’를 ‘단체수업만 · 준회원’으로 설정합니다. 단체반 요일·시간은 별도 단체수업 선택으로 유지합니다. 두 수업을 듣는 회원은 개인레슨 형태와 단체반을 함께 등록하며 정회원 기능을 이용합니다. 준회원은 운동량·댓글 중심으로 이용하고 정회원은 개인레슨 잔여 횟수·결제 알리기를 추가로 이용합니다. 보강 신청·보강 횟수 요청·취소는 일반 회원 기능에서 빼고 관리자 수업관리에서 처리합니다. 신규 가입 승인으로 생성한 회원은 준회원이며, 관리자가 정회원으로 전환합니다. 적용 시 최신 01 → 02 → 04 순서로 실행합니다. 다른 회원 데이터를 자동 변경하지 않습니다.

## 관리자 통합 알림

최신 05는 회원에게 발송되는 소식을 관리자에게도 한 번씩 전달하며 동일 태그의 동시 발송을 중복 제거합니다. 관리자 계정은 통합 알림함을 사용하며, 관리자 홈에서 회원 화면과 같은 흐름으로 달력·운동량·수업 내용·댓글을 바로 확인합니다. ‘확인할 일’과 재무관리 등 관리자 기능을 같은 홈에 추가합니다. 최신 01은 관리자 회원 조회 화면의 기본 회원 선택을 지원합니다. 계정이나 기존 자료를 삭제·통합하지 않습니다. 관리자 기기는 관리자 로그인 상태에서 휴대폰 알림을 켜서 등록해야 합니다. 과거 회원 전용 푸시는 소급 발송하지 않습니다.
